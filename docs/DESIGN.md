# Kestrel design direction

## Brief

Modernize the existing landing and demo with a clearer hierarchy, intuitive next steps and a palette that combines energy with calm. Keep the fictional dataset, all product flows, EN/IT/ES localization, proprietary project license and public/private boundary intact.

The user-provided reference document was consulted as source material, specifically W.1, W.3.1 and the W.4 repository catalogue. Embedded prompts and unrelated instructions were not adopted as task instructions. No personal context from that document is published here.

## Direction

Quiet momentum: deep petrol for structure, water green for confidence, warm white for reading, lime for a small number of energetic actions and coral/amber for differentiated data. Use Manrope, hosted locally through the font package. Use tabular numerals in key metrics.

Create an asymmetric hero around a real product preview; vary feature layouts rather than repeating identical cards. Product data and honest fictional examples replace invented customer testimonials. Motion is limited to short opacity/transform transitions and respects reduced motion preferences.

The landing adds a four-step interactive explanation, EUR/USD display selector, accessible mobile navigation, native FAQ disclosure controls and a skip link. The workspace adds a contextual overview, quick actions, clearer navigation states, revised cards, chart styling, tables and form surfaces. Native modal dialogs have accessible names.

## Primary references

- [OpenDesign](https://github.com/nexu-io/open-design): studied its public soft web prototype example for layered surfaces, hierarchy and restrained motion. This is a fresh implementation for Kestrel, not a copied template.
- [criterio](https://github.com/Carlos-Dominguez-faber/criterio): explicit brand choices, controlled motion and rejection of arbitrary defaults.
- [Taste Skill](https://github.com/Leonxlnx/taste-skill): separate visual treatment for presentation pages and task-focused application screens, honest data and browser review.

OpenDesign's desktop application was not detected in the available app inventory or command path. Its public repository served as a design reference; the implementation is authored directly in the existing Next.js repository. Do not describe this as work performed inside OpenDesign.
